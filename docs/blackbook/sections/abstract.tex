\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

\noindent Educational institutions still manage teaching resources, question
banks, and examinations through manual, document-centric workflows. Materials
are scattered across files, syllabus documents are interpreted by hand,
questions are compiled without quality control, and assessments are distributed
and evaluated without structured feedback. This project designs and implements
\textbf{EduTech}, a multi-tenant web platform that assists colleges with
course-content preparation and examination management. The system provides
institute-level tenancy with role- and permission-based authorization,
structured academic structure (years, classes, divisions, subjects, and
teacher--student assignments), OCR-based extraction of uploaded materials, and
AI-assisted generation of structured content --- syllabus structuring, study
notes, flashcards, summaries, concept summaries, and question banks --- driven
through an internal AI gateway. It implements paper patterns, question papers,
and scheduled assessments with server-side evaluation of objective answers
(MCQ, true/false, fill-in-the-blank, matching, and numerical), result analytics,
exam-paper and question-bank exports, and an ungraded practice mode with
flashcard and question sessions.

\noindent The system follows a modular-monolith architecture: a NestJS API on
PostgreSQL (Drizzle ORM), a Next.js web client, asynchronous TypeScript-worker
and Python-worker services connected through RabbitMQ, a separately deployable
FastAPI OCR service (PyMuPDF embedded-text extraction with PaddleOCR fallback),
and a purely local, provider-gatewayed AI integration. It is deployed as a
Docker Compose stack behind a reverse proxy and Cloudflare Tunnel, following a
defense-in-depth security design: short-lived session-bound access tokens,
strict rotating refresh sessions, double-submit CSRF protection, DB-fresh
permission evaluation with an explicit permission catalogue (83 permission
keys over 19 resources), tenant isolation enforced at every query, and academic
scope enforcement that resolves the actor's subject set from current database
state rather than from token claims.

\noindent The implementation is validated by 226 passing unit tests and eleven
database-integrated test suites, complemented by systematic manual validation.
The platform is deliberately multi-tenant and tenant-isolated, employs
asynchronous, non-blocking processing for OCR and AI generation, and keeps the
public API a single boundary behind an edge tunnel, so that no internal service
is exposed to the public network.

\vspace{1em}
\noindent\textbf{Keywords:} multi-tenancy, modular monolith, OCR, large language
models, question-bank generation, assessment evaluation, role- and
permission-based access control, academic scope, NestJS, PostgreSQL, RabbitMQ,
Next.js.

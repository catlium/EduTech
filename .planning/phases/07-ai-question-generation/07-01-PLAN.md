<objective>
Build AI question generation + review for Phase 7: a worker operation that generates
validated, PENDING questions from source materials, an API endpoint that enqueues
the job and returns its status/results, reuse of the Phase 6 edit/approve/reject
actions, and batch approve/reject. AI-generated questions land PENDING by design
(AIGQ-08), never auto-approve.
</objective>

<task type="auto">
  <name>Task 1: Worker — AI_GENERATE_QUESTIONS operation (schemas, prompt, service, db)</name>
  <files>
    apps/workers/worker/ai/schemas.py
    apps/workers/worker/ai/generation/questions.py
    apps/workers/worker/ai/generation/__init__.py
    apps/workers/worker/ai/service.py
    apps/workers/worker/db.py
  </files>
  <action>
    1. `schemas.py`: add a Pydantic mirror of the question generation output — a list
       of questions, each with stem, questionType (Literal MCQ|TRUE_FALSE|FILL_IN_BLANK),
       difficulty (Literal EASY|MEDIUM|HARD, default MEDIUM), explanation (optional),
       and payload, which is validated per type:
       - MCQ: choices[{id,uuid,text}], correctChoiceId (uuid, must reference one of choices) + a top-level schema for the AI to output ids, then map to final QuestionPayload.
       Keep the AI payload as the canonical QuestionPayloadSchemas equivalent in Pydantic:
       `McqChoice{id,text}`, `McqPayload{choices,correctChoiceId}`, `TrueFalsePayload{correctAnswer}`,
       `FillInBlankPayload{acceptableAnswers}`. GeneratedQuestion model: `stem`, `questionType`,
       `difficulty`, `explanation`, and a `payload` discriminant field per type.
    2. `generation/questions.py`: `build_messages(context, source_label, params)` returns
       system+user messages instructing the model to output a JSON object
       `{"questions": [...]}` with exactly `count` questions of the given `questionType`
       and `difficulty`. `parse_questions_json(content)` → dict via `parse.parse_json_object`.
    3. `generation/__init__.py`: import questions module.
    4. `service.py`: add `AI_GENERATE_QUESTIONS` to `OPERATIONS`, but because this
       operation persists questions (not content), add a special branch in `generate()`
       (or a dedicated `generate_questions`) that, after validation, calls
       `db.insert_generated_questions(...)` and returns question IDs in the job result.
       The `Operation` model gets a `persist` callable OR handle it inline; simplest is an
       inline branch keyed by operation, reusing resolve_materials/build_context. Params
       (count, questionType, difficulty) are read from the job payload.
    5. `db.py`: add `insert_generated_questions(institute_id, *, questions, created_by)`
       where each item inserts into `questions` (subject_id/chapter_id/topic_id from the
       resolved source scope, stem, question_type, difficulty, explanation, payload jsonb,
       source='AI_GENERATED', approval_status='PENDING', status='ACTIVE', created_by,
       updated_by=created_by) RETURNING id. Returns list of ids.
  </action>
  <acceptance_criteria>
    - Python module imports cleanly; no NameError for the new operation.
    - ruff check + mypy pass on the worker.
    - The AI_GENERATE_QUESTIONS operation resolves scope, builds context, and persists PENDING questions.
  </acceptance_criteria>

    1. Add a `QuestionGenerationService` (or extend QuestionsService): `requestGeneration`
       validates source scope (exactly one of subject/chapter/topic, in-institute),
       builds job payload {operation:'AI_GENERATE_QUESTIONS', source:{type,id},
       requestedBy, params:{questionType,count,difficulty}}, uses JobsService.createJob,
       returns {jobId, ...}. `getGenerationResult` reads the job row (scoped) and returns
       status + result.
    2. Controller: add
       - `POST /questions/generate` → 202 (teacher/admin) → { generation }

       - `POST /questions/batch-reject` body {questionIds:[...]} → { updated }
    3. DTO: GenerateQuestionsDto (scope fields subjectId/chapterId/topicId exactly one,
       questionType, count int 1..50, difficulty optional), BatchQuestionActionDto (questionIds uuid[]).

    5. Wire the new service into QuestionsModule providers.
